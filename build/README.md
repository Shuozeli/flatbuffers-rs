# flatc-rs-build

`flatc-rs-build` integrates the Rust FlatBuffers generator with Cargo build
scripts. It tracks direct schemas and all transitive includes with
`cargo::rerun-if-changed`, writes generated Rust into `OUT_DIR`, and avoids
rewriting files whose generated contents are unchanged.

## Setup

Add the helper as a build dependency. The compiler is currently distributed
from reviewed repository revisions:

```toml
[dependencies]
flatbuffers = "25.12.19"

[build-dependencies]
flatc-rs-build = { git = "https://github.com/Shuozeli/flatbuffers-rs.git", rev = "<reviewed-revision>" }
```

Generate one self-contained Rust source from a root schema and all its includes:

```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    flatc_rs_build::Builder::new()
        .schema("schemas/game.fbs")
        .include_dir("schemas")
        .gen_all()
        .compile()?;
    Ok(())
}
```

Include the generated source from the crate:

```rust
include!(concat!(env!("OUT_DIR"), "/game_generated.rs"));
```

## Output Model

Each direct schema produces `{schema_stem}_generated.rs`. By default, each file
contains only declarations owned by that direct schema, matching the `flatc`
CLI without `--gen-all`. Register included schemas as direct inputs when the
consumer wants separate generated modules:

```rust
flatc_rs_build::Builder::new()
    .schemas(["schemas/shared.fbs", "schemas/game.fbs"])
    .include_dir("schemas")
    .compile()?;
```

Use `gen_all()` when one direct root should produce one self-contained output.
Inputs with the same file stem are rejected because they would overwrite the
same output path.

## Incremental Behavior

- Cargo skips the entire build script when no watched schema mtime changes.
- Direct and transitive `.fbs` files are emitted as `cargo::rerun-if-changed`.
- `rerun_if_env_changed()` tracks user-controlled codegen environment inputs.
- If the build script runs but generated bytes are unchanged, the output is not
  rewritten and its mtime is preserved.
- Cargo still considers a build script dirty when a watched file's mtime changes;
  this helper cannot add Bazel-style content pruning to Cargo itself.

## Builder Options

| Method | Effect |
|---|---|
| `schema`, `schemas` | Add direct FBS roots |
| `include_dir` | Add an include search path |
| `gen_all` | Emit declarations from transitive includes |
| `gen_name_strings` | Generate fully-qualified type name constants |
| `gen_object_api` | Generate owned Object API types and pack/unpack methods |
| `rust_serialize` | Generate serde implementations |
| `no_includes` | Omit generated dependent-schema imports |
| `no_leak_private` | Enforce private-type exposure and crate visibility |
| `rust_pluggable_buffer` | Generate `FlatBufferRead`-backed readers |
| `filename_suffix` | Replace the default `_generated` suffix |
| `rerun_if_env_changed` | Track a user environment variable |
| `out_dir` | Override `OUT_DIR` for tests or standalone tools |

`compile()` emits Cargo directives to stdout. `compile_with_writer()` exposes
the same behavior for tests and alternate build-system adapters. Both return a
`BuildOutput` containing generated, updated, and watched source paths.

The full behavior, cache boundary, and troubleshooting guide is in
[`docs/cargo-build-integration.md`](../docs/cargo-build-integration.md).
